## Failure Handling

- After any command changes the discovery document or dependency manifest, the prior active receipt is stale. Record the correction, close the producer run failed, create a fresh selection for the new bundle, run `activation`, and only then start or guard the successor run. A fresh `selection` without a following `activation` is not sufficient and produces `active-state-receipt-mismatch`.
- A stage-result envelope must reconcile every assigned gap: each `assigned_gap_id` appears in exactly one of `open_gap_ids` or `closed_gap_ids`. Include previously terminal gaps in `closed_gap_ids` without repeating their transition; add `record_transitions` only for statuses that change in the current attempt.
- Gap lifecycles are monotonic: `record_transitions` supports only `open -> closed|superseded|non-gap`. When a fresh assessment finds a distinct remaining defect in the category of a terminal gap, preserve the terminal ID in `closed_gap_ids` and create a new open gap with concrete recurrence/lineage evidence; never emit `closed -> open`.
