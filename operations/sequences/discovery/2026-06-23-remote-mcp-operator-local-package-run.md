## Intended Outcome

Run the sendable remote-mcp-operator package locally without depending on host Python site-packages.

## Why This Looks Repeatable

Local and sendable package verification repeatedly invokes dist/remote-mcp-operator; dependency bootstrap must be reusable for future package runs.

## Required Inputs, Auth, Or Environment

- Python 3.10 or newer available as `python3`, or set `WORKFLOW_ORCH_OPERATOR_PYTHON`.
- Network/package-index access on the first cold run unless the package-local `.venv` is already populated.
- No auth secrets are needed for `--help` or dependency import verification.
- For local container JWT-auth workflow runs, invoke the package from a neutral working directory such as `/private/tmp` so the repo-root `.env` is not loaded.
- For local container JWT-auth workflow runs, pass only `WORKFLOW_ORCH_WS_URL` and `WORKFLOW_ORCH_JWT_SECRET` as auth environment. Do not pass `WORKFLOW_ORCH_USER_EMAIL` or `WORKFLOW_ORCH_TOKEN_KEY`; keep the actor email in the MCP payload through `--actor-email`.
- For local container workflow runs, `--repo` must be the copied in-container project path, for example `/workspaces/neocurrency-dashboard/neocurrency-dashboard`, because the local server treats `--repo` as `workflow.project.set(projectPath=...)`.
- For a fresh playbook package run with the same prompt/repo/branch/actor as an old failed or completed checkpoint, pass `--existing-task-action start_over`; otherwise `playbook-start` may resume the checkpointed task/run by design.
