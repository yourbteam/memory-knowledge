# Atom 11 — grounded claims and operator commands

Frozen before canonical implementation. `frozen-red/run/` preserves the complete real Claude v3
run, including the cell whose second seat selected the exact whole producer line `Always-on after
launch.` and was refused solely because the collapsed line is 23 characters. The cell became
`recording-refusal`, did not enter the owner queue, and did not stop `document`. The same package
preserves the state and six-source registry used to open the run, the 16-item assessment and hand-
filed rulings, and the 165-line located digest written by the operator.

## Producer grounding and owner visibility

One shared code predicate owns both the reader instruction and intake refusal: an upstream quote is
grounded when its whitespace-collapsed text is an exact passage of at least 25 characters from the
registered source, or when it equals one entire non-empty source line after whitespace collapse.
The instruction and refusal state that same rule. The exact 23-character line passes; changing one
character fails.

Per-cell atomic recording still retains both raw seat claims when any claim cannot ground. Instead
of terminal `recording-refusal`, that cell is `unresolved` with outcome
`claim-without-grounded-words`, the exact failures, and all raw claims. It therefore appears in
`ask-owner`. The owner receives the normal three choices; `reject` or `revise` still requires
grounded page words. `document` refuses while this owner question remains.

## Derived opening

`open --from-run STATE.json --deliverable tactical_roadmap` is additive to the unchanged explicit
`--payload` and `--upstream-source` contract. It resolves exactly one namespace containing the
deliverable, then derives its declared producer set from the critique machinery's fixed deliverable
profile. For `tactical_roadmap`, that set is communications platform, message architecture,
strategy one-pager, big idea, execution toolkit, and measurement framework. A missing deliverable
or producer refuses before the run directory is created. The command prints the resolved payload
key and complete source id/key/value-hash list.

## Atomic bulk rulings

`rule-bulk` parses the assessment's summary table and numbered grounding sections. It preflights the
entire document against the current ordered owner queue: exact row count, unique complete row
numbers, lens identity, offered choice, and non-empty grounding. Only after every check passes does
it write the matrix, owner-rulings, and emptied owner queue together. Each `because` starts with the
operator's `--by` words followed by ` — reasoning drafted by Claude, adopted by the owner: ` and
the assessment grounding. Any refusal writes nothing.

## Located evidence

`located` reads only the run's immutable manifest, source registry, matrix, and persisted reader
responses. `--only disputed` selects disagreements and agreement defects; `defects` selects agreed
or owner-resolved reject/revise findings; `all` selects every applicable recorded cell. It prints
the unit label, both seat verdicts and spans, exact page lines, and source lines for upstream claims.
It launches no reader.
