# Prevention-system successor research

## Result

The current system has strong local mechanisms—closed work-memory events, guarded exact-argv execution, post-run discovery observation, atomic promotion, a resumable research kernel, and workflow-state persistence—but it does not satisfy the prevention system end to end. The stable boundary is a new authoritative typed prevention controller, not more parser aliases: one owner adapter per registered sequence, one closed operation registry, host-owned interception before dispatch, mandatory verified-successor selection, one causal learning lineage, full-unit admission, a common effect journal, and canonical system metrics.

## Current findings

1. Entry points: the registry has 25 rows. Several are composites, one is explicitly not standalone, and most automation internals are outside the finite evidence set. Those are not assumed; their owners must pass black-box initialization-to-terminal adapter acceptance.
2. Typed operations: work-memory events and the research Operation enum are closed and validated, but governed paths still accept request/context JSON files, JSON argv, command strings, arbitrary argv, free-text correction fields, and rendered registry text.
3. Interception: current guard and checked-exec are opt-in. Official PreToolUse can deny/rewrite Bash, apply_patch, and MCP. It does not completely intercept unified shell and does not intercept WebSearch/non-shell non-MCP tools. No coverage is proved for subagent or non-MCP remote dispatch. Unsupported classes must therefore be withheld structurally or depend on a future host hook; otherwise they must fail visibly.
4. Corrections: fingerprints, corrections, successor bindings, same-path verification, and closure exist, but no durable predecessor prohibition or mandatory future selector exists.
5. Learning: the observer can automatically propose discovery after a context-rich close, and the lifecycle can qualify/promote/verify. The later-reuse test links the promoted sequence only after the later seed action executes, so it proves post-hoc recognition, not prevention or mandatory reuse.
6. Budget: research admission reserves three timeout windows despite five mandatory roles and omits materialization, terminal emission, and bounded retries. Other long controllers have no proved full-unit admission.
7. Resume: research and promotion have strong local journals; bootstrap, reconciliation, work-memory, and workflow state have partial durable behavior. No common effect identity, branch ownership key, or crash matrix spans all owners.
8. Metrics: current metrics cover run quality, repeated blocker counts, observer links, and research-only timing. Required registered-use, raw-dispatch, prevented-failure, system-wide failure-time, promoted-reuse denominator, and real-run overhead queries are missing or partial.

## Acceptance boundary

Overhead is mechanical_seconds/governed_active_seconds. The hard gate is <=0.10 and the desired target is <=0.05; report both the observed ratio and whether each threshold passes. Exclude user-approval wait, external service/rate-limit wait, and intentionally productive model/domain execution only when separately event-classified. Never exclude local retries, command reconstruction, malformed-input recovery, guard work, selector work, or correction overhead. Registered use is registered_dispatches/eligible_recurring_actions over a fixed representative governed window and must be >=0.95. Zero-raw and zero-repeat assertions are event-backed negative tests, not prose claims.

## Material gaps

GAP-ENTRYPOINT-SYSTEM-WIDE, GAP-TYPED-DISPATCH, GAP-AUTHORITATIVE-INTERCEPTION, GAP-MANDATORY-CORRECTION, GAP-CAUSAL-LEARNING, GAP-FULL-UNIT-ADMISSION, GAP-COMMON-DURABLE-RESUME, and GAP-SYSTEM-METRICS are planner-owned implementation gaps.
